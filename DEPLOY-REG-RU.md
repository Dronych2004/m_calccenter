# Деплой CalcCenter на REG.RU: исправление переадресаций

Сборка готова в G:\development\mimo\calccenter\dist.
Архив calccenter-reg-ru.zip содержит файлы сайта непосредственно в корне, без папки dist.

## Порядок загрузки

1. Сделайте резервную копию текущей папки сайта через файловый менеджер хостинга. Сохраните копию вне публичной папки сайта или скачайте её.
2. Откройте именно корень calccenter.ru: там находятся index.html, index.php и .htaccess.
3. После резервного копирования удалите старые папки калькуляторов из списка ниже. Удалять следует только папки прежней сборки, содержащие index.html. Если внутри есть ваши дополнительные файлы, сначала сохраните их. Новая сборка использует одноимённые .html-файлы, а публичные адреса остаются прежними.
4. Загрузите архив в корень сайта и распакуйте с заменой файлов. Проверьте, что .htaccess тоже заменился: скрытые файлы должны отображаться. index.php, index.html, osago.html, credit.html, sw.js и assets должны лежать рядом. Если используется загрузка dist вручную — загружайте её СОДЕРЖИМОЕ, а не саму папку.
5. Удалите загруженный ZIP из публичной папки после распаковки. Не меняйте PHP, SSL или настройки nginx в панели. Файл nginx.conf в сборке — пример для отдельного сервера; его загрузка сама по себе не применяет настройки REG.RU.
6. Закройте все окна инкогнито, откройте новое и проверьте страницы ниже прямой вставкой адреса. Это исключит старый Service Worker и сохранённые редиректы обычного профиля.
7. Только после успешной проверки сайта запускайте повторную проверку ошибки переадресации в Google Search Console.

## Проверка после загрузки

- https://calccenter.ru/ — главная открывается.
- https://calccenter.ru/osago — калькулятор открывается без изменения адреса, HTTP 200.
- https://calccenter.ru/osago/ — один редирект 301 на /osago, затем 200.
- https://calccenter.ru/credit и /credit/ — аналогично.
- Проверить /util-fee, /vacation, /classic, /wallpaper, /penalty.
- Обновить страницу калькулятора клавишей F5 — она должна продолжать открываться.
- https://calccenter.ru/definitely-not-a-page — страница «не найдена», HTTP 404.
- https://calccenter.ru/sitemap.xml — файл открывается, адреса калькуляторов без завершающего слеша.

В Google Search Console можно сначала открыть «Проверка URL» для /osago и выбрать проверку опубликованной страницы. Затем запустить проверку исправления общей ошибки. Исторические записи не исчезнут сразу: Google должен повторно обойти адреса.

Если цикл остаётся в новом инкогнито, пришлите скрин двух соседних запросов 301 из вкладки «Сеть» с раскрытыми заголовками: Request URL и Location. Это покажет, какое правило REG.RU ещё вмешивается.

## Что изменено и проверено

- Пререндеринг создаёт 23 HTML-файла: главную и 22 калькулятора. Папки маршрутов больше не создаются.
- Apache передаёт чистые адреса в PHP; PHP отдаёт соответствующий .html и возвращает 404 для неизвестного адреса.
- Переадресации явных .html-адресов отделены от внутренней обработки.
- Service Worker v4 очищает старый кеш, не перехватывает навигацию и не подменяет ошибку сети главной страницей. Офлайн-открытие HTML теперь не поддерживается.
- Пререндеринг запускается напрямую через Puppeteer; проверяет загрузку заголовка страницы и canonical перед сохранением.
- npm run build прошёл полностью; 23 страницы проверены на canonical, h1, наличие ресурсов и отсутствие старых папок.
- npm test: 31 тест прошёл. Lint прошёл без ошибок, имеются прежние предупреждения.
- Проверено, что Service Worker пропускает навигацию, удаляет старый кеш и загружает статику.
- Реальные Apache/PHP REG.RU локально не запускались. Из среды разработки запросы к сайту завершаются тайм-аутом, поэтому окончательное подтверждение HTTP-ответов возможно после вашего деплоя.

Для повторной сборки обычно достаточно npm run build. Если встроенный Chromium в вашей среде не запускается, можно указать установленный Chrome (PowerShell):

$env:PRERENDER_BROWSER_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
$env:PRERENDER_PROFILE_PATH="$env:TEMP\calccenter-prerender"
npm.cmd run build

В ограниченной среде этой проверки дополнительно использовался PRERENDER_NO_SANDBOX=1; на обычном компьютере включать его без необходимости не нужно.
